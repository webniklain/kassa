# Касса — Product Vision

## Название

**Касса**

## Назначение

«Касса» — простое семейное приложение для ежедневного учёта расходов и приходов.

Главная задача приложения — не вести бухгалтерию, а в любой момент показывать:

- сколько денег доступно в текущем месяце;
- сколько уже потрачено;
- сколько осталось;
- на какие категории уходят деньги.

## Для кого создаётся приложение

Первая версия создаётся для одной семьи:

- Андрей;
- Наташа.

Приложение должно учитывать совместные семейные расходы и синхронизировать данные между двумя пользователями.

## Главная ценность

Пользователь должен быстро получить ответ на главный вопрос:

> Сколько денег осталось до конца месяца?

## Основные сценарии

### Записать расход

Пользователь указывает:

- сумму;
- категорию;
- необязательное описание;
- дату;
- при необходимости — фото чека.

Название магазина не является обязательным и не хранится как отдельная сущность.

### Записать приход

Пользователь указывает:

- сумму;
- необязательное описание;
- дату.

Приход увеличивает доступный остаток текущего месяца.

### Посмотреть состояние бюджета

На главном экране отображаются:

- остаток;
- расходы за сегодня;
- расходы за неделю;
- расходы за месяц;
- последние записи.

### Управлять категориями

Категории не задаются жёстко навсегда.

Пользователь может:

- выбрать существующую категорию;
- создать новую категорию прямо во время записи расхода;
- использовать категории, которые действительно нужны семье.

## Принципы продукта

1. Любое частое действие должно занимать не более 5 секунд.
2. Каждый экран решает одну основную задачу.
3. Необязательные поля не должны мешать быстрому вводу.
4. Категория важнее названия магазина.
5. Магазин не является отдельной сущностью.
6. Новую категорию можно создать прямо во время добавления расхода.
7. Основная валюта первой версии — GEL.
8. Интерфейс первой версии — на русском языке.
9. Приложение должно быть удобно на iPhone.
10. Новая функция добавляется только тогда, когда она экономит время или помогает принимать решение.

## Что не входит в первую версию

- банковские интеграции;
- автоматический импорт операций;
- сложная бухгалтерия;
- долги между пользователями;
- инвестиции;
- несколько бюджетов одновременно;
- десятки графиков;
- управление магазинами;
- обязательное распознавание чеков;
- App Store.

## Технологический принцип

Первая версия должна оставаться максимально простой:

- HTML;
- CSS;
- JavaScript;
- локальное хранение на этапе прототипа;
- облачная синхронизация на следующем этапе;
- без сложного фреймворка и большого количества зависимостей.

## Критерий успеха

Приложение считается успешным, если Андрей и Наташа ежедневно записывают в него расходы без ощущения, что это неудобная обязанность.
